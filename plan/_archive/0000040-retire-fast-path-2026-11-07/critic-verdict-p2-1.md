## Findings (severity-ordered)

- [major] ADR-003 Reading product.yml and When the read fails, req-003, `risk-register.md`: pre-push fails closed when the base commit can't be resolved. Build log line 177 fixes that base as the merge base with `origin/main`. Setup sets `core.hooksPath ravintio-framework/hooks` (`setup.sh` `activate_guardrails`), so this pre-push runs in every consumer repo. Some repos have no `origin/main`. One example is a consumer whose default branch is `master`, which `hooks/ravintio.yml` accepts under `branches: [ main, master ]`. Another is a repo whose first push creates `main`. In both cases, after this change every push blocks for good. Today the same case fails open, because `git diff` errors and `CHANGED_FILES` comes back empty. R-011 covers only a shallow CI clone. ADR-003 lists only "a shallow clone or a failed `git fetch`" as a temporary block. No alternative, risk, or fixture covers a missing base branch. Fix: decide how pre-push resolves its base, for example from the upstream, `origin/HEAD`, or a `main` then `master` fallback. Or limit fail-closed to CI and state what pre-push does instead. Record the choice in ADR-003, add a risk row, and add a req-003 fixture.
