## Findings (severity-ordered)
- [major] `requirements/req-001-windows-safe-0000041-suites.md`: the `pwd -W` FR converts `WORK` only. The two `projectKind(root)` cases also embed `$PK` in the `node -e` string, and `$PK` is `$FW/scripts/project-kind.mjs`. `pack-root.sh` builds `$FW` with `pwd`, so on Git Bash it stays POSIX form (`/d/a/...`). MSYS converts argv, not text inside a `-e` script. `pathToFileURL('/d/a/...')` on Windows then resolves to `D:\d\a\...`, and the import still fails. Add an FR that `PK` (or `FW`) also reaches Node in Windows form, for example `pwd -W` or `cygpath -m`, and state it in `design.md` and A-003.
- [major] `requirements/req-001-windows-safe-0000041-suites.md`: the SKIP-line count contradicts itself. FR 3 says the four link cases skip "with one `SKIP (windows)` line". AC3 and the glossary's "Windows skip" entry say each skipped case prints one line. `tests/README.md` says "Each guard has one row here, and each row has one guard", while the design adds one row per suite. The four link cases sit at four separate places in the suite, not in one block. State one rule: one guard and one line for all four cases, or four guards with four lines and four README rows. Then align AC3, the glossary, the design, and the README row count to it.
- [minor] `risk-register.md`: R-001's mitigation ("Linux and macOS still run every link case") and R-004's mitigation ("`git hash-object` reads the working-tree file at `$FW`") state facts, not actions. Name an action, such as a probe that runs the link cases when `test -L` holds after `ln -s` (R-001), or an assertion that `$REL` sits under `RAVINTIO_PACK_REL` (R-004).
- [minor] `risk-register.md` R-002 against `build-log.md` and `design.md`: the register says "P3 pushes the fix and reads the Windows shards before P7". The Decision line says "after the P4 CI pass, push the branch". The design's Risks entry says only "the PR checks are the final proof". Pick one phase and state it in all three.
- [minor] `feature-brief.md` In Scope against `req-001` FR 5: the brief and backlog 0000426 compare blob ids at `HEAD` and `v0.38.0`. The requirement compares `v0.38.0` with `git hash-object` of the working-tree pack copy. These check different things, because only the second catches an uncommitted edit. Align the brief to the requirement. Also state that `git hash-object` runs inside the repo (for example `git -C "$RAVINTIO_REPO_ROOT" hash-object`), so that `core.autocrlf` applies.
- [minor] `requirements/req-001-windows-safe-0000041-suites.md`: the AC3 assertion label in the suite reads "byte-identical to v0.38.0". After the blob compare, that label describes a check the suite no longer makes. Add an FR to reword the label to the blob id compare. AC2 then still counts 67 passes.
- [minor] `execution-plan.md` A-003 and `design.md` Assumptions: Node on the Windows runner resolves `/tmp/...` against the current drive, which is `D:` under `D:\a\...`, not `C:`. The stated example names the wrong drive. The impact holds either way.
