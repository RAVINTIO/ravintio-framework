### What Was Built

Version 0.38.0 retires Fast Path and the Change Pipeline. Every change, with or without a `src/` target, now runs the Feature Pipeline. The feature folds in backlog 0000358, 0000152, and 0000200, with seven requirements under three user stories.

- **One-track routing (req-001):** the orchestrator, both phase 0 references, the boot template, the other skills, and the docs route every request to the Feature Pipeline. Triage stays only for the standalone skills: optimise, refresh setup, and retrofit.
- **Gates ignore the scope record (req-002):** `gate-write`, `shell-write-guard`, and `ratchet-check` no longer read `plan/.fast-path-scope`. The enforcement path list survives as `ENFORCEMENT_PATHS` (ADR-004). The two write gates stay in parity.
- **No commit subject exemption (req-003):** pre-push, `hooks/ravintio.yml`, and this repo's CI file lose the `fix(fast-path):` exemption. Each gains the source folder rule, which reads component folders from `product.yml` at the base commit and at HEAD (ADR-003).
- **Track files removed (req-004):** the pack no longer holds these files:
  - `workflows/fast-path.md`
  - `workflows/change-pipeline.md`
  - `skills/ravintio-change-agent/`
  - `templates/change-summary.template.md`

  `setup.sh` and `setup.ps1` remove the installed copies through a named retired list, with or without a manifest (ADR-005).
- **Consumer migration (req-005):** `migrate-0.38.0-retire-fast-path-and-change-pipeline.md` asks the human on the loop to delete a leftover scope record. It removes the CI exemption block once the human on the loop confirms. Migrator rule 1 widens for paths that a migration names on a `**May edit:**` line, and `src/` stays closed (ADR-006).
- **Residue guard (req-006):** a suite fails on any live reference to either track outside a closed allowlist with line regexes (ADR-007).
- **Docs and ADR notes (req-007):** the living docs describe one track. `docs/decisions-index.md` marks five earlier ADRs superseded or partly superseded. The pack manifest reads 0.38.0, and P7 sets `product.yml` and `docs/about.md`.

P5 rated the feature low. Three parallel reviewers ran real fixtures in scratch repos and found 15 findings: 1 Medium, 12 Low, and 2 Info. The Medium, S-1, showed that `gate-write` blocks the migration's CI edit in a hooked consumer with no design. The record then read `applied`. Defect report 001 petitioned for a reversal, and the assessor denied it as altering. A P5 TDD fix (`deaf863f`) added the `skipped` reasons `blocked` and `refused` and a linked `plan` check. The human on the loop then chose option 3 for exception 001: the block stays, and the record reads `skipped` (R-014). Backlog 0000372 to 0000377 hold the open Low and Info findings.

### Upgrade steps for a consumer

1. Copy the new `ravintio-framework/` folder into the project root.
2. Let the migrator run `migrate-0.38.0-retire-fast-path-and-change-pipeline.md` at the next session start.
3. If the migrator asks, delete `plan/.fast-path-scope` with `rm -- plan/.fast-path-scope` from the project root.
4. Confirm or decline the removal of the 14-line exemption block from `.github/workflows/ravintio.yml`.
5. If the record reads `skipped`, delete the lines it names by hand. In a consumer with the hooks installed and no design, `gate-write` blocks the edit, so this step is the normal case.
6. Re-run `ravintio-framework/setup.sh` or `setup.ps1` for each tool the project uses, with its usual flags. The re-run removes the installed track files.
7. Compare your CI file with `ravintio-framework/hooks/ravintio.yml` to take the source folder rule. The migration removes only the exemption block (backlog 0000364).

If a run of either retired track is unfinished, restart it on the Feature Pipeline.
